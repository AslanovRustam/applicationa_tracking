# Трекер откликов на вакансии — дизайн

Дата: 2026-11-23

## Зачем

Пользователь (frontend-разработчик, React/Next.js) больше трёх месяцев ищет работу: 200+ откликов, одно собеседование. Сейчас отклики записываются в Google-таблицу (вкладка «отклики»), и это неудобно:

- нет отдельного статуса: отказ пишется текстом в колонку «1 собес» и заливается красным, поэтому отфильтровать или посчитать отказы нельзя;
- ЗП записана как попало (то в $, то в грн, то с комментарием);
- шаблоны сопроводительных писем и ссылки на резюме и соцсети приходится каждый раз искать и копировать вручную.

Нужно личное веб-приложение, в котором отклики **быстро записываются и за ними удобно следить**, плюс отдельная страница «Копилка», откуда шаблоны и ссылки копируются в один клик. Работать с ним будут с телефона и с ноутбука. Хостинг — Vercel.

Аналитика воронки (почему почти нет ответов) — следующий этап, его делаем в другой раз. Но данные собираем уже сейчас так, чтобы потом её можно было построить: источник, даты, история статусов.

## Цели

1. Добавить отклик быстрее, чем строку в Google-таблице.
2. С первого взгляда видеть, что происходит: сколько откликов за неделю, что сейчас в процессе, когда ближайший собес.
3. Удобно искать и фильтровать сотни откликов.
4. Хранить историю этапов каждого отклика (когда отправлен, когда скрининг, когда отказ).
5. «Копилка»: шаблоны и ссылки, которые копируются в один клик, с подстановкой компании и должности из отклика.
6. Нормально работать и на телефоне, и на ноутбуке.

## Не цели (в этой версии)

- Аналитика и графики воронки.
- Быстрая панель Ctrl+K.
- Офлайн-режим.
- Несколько пользователей.
- Уведомления и напоминания.
- Автоматический разбор страницы вакансии по ссылке (подтянуть компанию и должность). Хорошая идея на потом.

## Анти-цели (провал, даже если всё «работает»)

- Добавлять отклик медленнее или муторнее, чем в таблице.
- Данные потерялись или испортились.
- Отклики, заметки и личные ссылки видны кому-то, кроме владельца.
- Приложение заперто в одном сервисе: данные должны оставаться в Google-таблице владельца.

## Ограничения

- Деплой на Vercel.
- Хранилище — **отдельный файл Google-таблицы**, который создаёт пользователь. Выбрано, чтобы данные были под рукой и не зависели от ещё одного сервиса. Пользователь в эту таблицу руками не пишет: открывает только чтобы посмотреть или сделать копию. Писать в неё может только приложение.
- Пользователь один. Ссылка на Vercel публичная, поэтому вход обязателен.
- Бесплатные тарифы: Vercel Hobby, Google Sheets API.

## Рассмотренные подходы

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Next.js + Google Sheets API** | Бесплатно, ничего не «засыпает», данные в Google-таблице владельца, легко выгрузить | Каждое действие на 0,3–1 с медленнее, чем с базой; нет транзакций; аналитику считать в коде | **Выбран пользователем**: данные под рукой, без лишнего сервиса |
| Next.js + Supabase | Меньше всего частей, вход и защита данных из коробки, быстро | Ещё один сервис; бесплатный проект засыпает после недели простоя | Рекомендовался, но пользователь предпочёл таблицу |
| Next.js + Neon + Auth.js | Всё на Vercel, база не засыпает | Больше частей (ORM, библиотека входа, OAuth) | Отклонён |

## Как устроено

### Стек

- Next.js (App Router, TypeScript), деплой на Vercel.
- Работа с Google Sheets **только на сервере** (Server Actions или Route Handlers) через служебный аккаунт Google. JSON-ключ лежит в переменных окружения Vercel, ID таблицы тоже.
- Вход: Auth.js (NextAuth) с провайдером Google, пускают только email из переменной `ALLOWED_EMAIL`. Сессия долгая, чтобы на телефоне не приходилось входить каждый раз. *(Моё решение: у пользователя всё равно есть Google-аккаунт, и OAuth-клиент живёт в том же Google Cloud-проекте, что и служебный аккаунт.)*
- UI: Tailwind CSS + shadcn/ui. *(Моё решение: быстро, привычно для React-разработчика.)*
- PWA: manifest и иконки, чтобы приложение ставилось на главный экран телефона. Без офлайна.
- Язык интерфейса: русский. *(Моё решение.)*
- Сам код может пойти в портфолио пользователя на GitHub, так что он должен быть аккуратным.

### Структура Google-таблицы

В файле четыре вкладки. Первая строка в каждой — заголовки. У каждой записи есть колонка `id` (UUID), и **приложение всегда ищет строку по `id`, никогда по номеру строки**. Даты пишутся строкой в ISO (`2026-08-14`, `2026-09-02T14:00`) с `valueInputOption: RAW`, чтобы Google не переделал их под свою локаль.

**`applications`** — отклики

| колонка | описание |
|---|---|
| id | UUID |
| applied_at | дата отклика |
| company | компания |
| position | должность |
| url | ссылка на вакансию |
| source | dou / djinni / linkedin / robota / workua / nofluffjobs / arbeitnow / himalayas / greenhouse / ashby / lever / smartrecruiters / dover / company_site / other; определяется по домену ссылки (`lnkd.in` = linkedin, любые `arbeitnow.*` = arbeitnow), можно поправить руками |
| status | см. статусы ниже |
| interview_stage | номер этапа собеседования (1, 2, 3…), пусто если не собес |
| next_event_at | дата и время ближайшего события (собес, звонок), может быть пустым |
| salary_asked | что просил, свободный текст (`3000$`) |
| salary_listed | вилка из вакансии, свободный текст (`4000–6000$`) |
| contact | контакт рекрутера (имя / telegram), свободный текст |
| notes | заметки |
| created_at, updated_at | служебные |

**`history`** — смены статуса (`id`, `application_id`, `status`, `interview_stage`, `at`, `note`). Запись добавляется при каждом изменении статуса. Это лента в карточке отклика и основа будущей аналитики.

**`vault_sections`** — разделы копилки (`id`, `name`, `order`).

**`vault_items`** — записи копилки (`id`, `section_id`, `type` = `link` | `text`, `title`, `content`, `tags` через запятую, `order`).

### Статусы

`sent` (Отправлен) → `screening` (Скрининг) → `interview` (Собеседование, с номером этапа) → `offer` (Оффер). Отдельно `rejected` (Отказ) и `ghosted` (Тишина).

Тишину приложение **не ставит само**: у откликов в статусе `sent` без движения 30+ дней показывается пометка «нет ответа 30+ дн» и кнопка «Отметить как Тишина». Ещё есть массовое действие «Отметить все такие как Тишина».

### Главная страница — трекер (выбран вариант «гибрид»)

1. **Сводка сверху**, 4 карточки: откликов за последние 7 дней; всего откликов; в процессе (`screening` + `interview` + `offer`); ближайшее событие (`next_event_at`, ближайшее в будущем — компания и время).
2. **Панель**: кнопка «+ Отклик», поиск (по компании и должности), фильтры-чипсы по статусу со счётчиками (Все / Ждут ответа / В процессе / Отказ / Тишина), фильтр по источнику. Переключатель «Таблица / Доска».
3. **Таблица**: дата, компания, должность, статус (цветная плашка), источник, ЗП. По умолчанию сортировка по дате, новые сверху; сортировка по клику на заголовок.
4. **Клик по строке** открывает панель справа (на телефоне — на весь экран): все поля с правкой на месте, ссылка (открывается в новой вкладке), смена статуса, лента истории, кнопка «Скопировать сопроводительное» (см. Копилку), удаление с подтверждением во встроенном окне, а не через `confirm()` браузера.
5. **Доска** показывает только активные отклики: колонки Скрининг / Собеседование / Оффер. Карточку можно перетащить в другую колонку или бросить в зону «Отказ»; каждое перемещение пишет запись в `history`.
6. **На телефоне** таблица превращается в список карточек (компания, должность, статус, дата), фильтры уходят в выпадающее меню, «+ Отклик» — плавающая кнопка.

**Добавление отклика** должно быть быстрым: первым идёт поле ссылки. После вставки ссылки источник определяется сам; дата — сегодня, статус — `sent`. Обязательные поля только компания и должность, остальное по желанию. Есть «Сохранить и добавить ещё». Отправка формы не ждёт Google: запись сразу появляется в списке (оптимистичное обновление), а если запись в таблицу не удалась, показывается ошибка и кнопка «Повторить».

### Страница «Копилка» (выбран вариант B)

- Разделы, которые пользователь **создаёт, переименовывает, переставляет и удаляет сам** (например «Ссылки», «Сопроводительные», «Ответы на частые вопросы», «Зарплатные ожидания»). При первом запуске создаются разделы «Ссылки» и «Шаблоны» как стартовые, их тоже можно менять.
- В каждом разделе записи двух типов:
  - **ссылка** — кнопка-чип с названием; клик копирует URL, рядом иконка «открыть»;
  - **текст** — карточка с заголовком, тегами, превью текста и кнопкой «Копировать».
- Записи можно добавлять, править, удалять и переставлять. Поиск по всем записям и фильтр по тегам.
- **Переменные в тексте**: `{компания}`, `{должность}`, `{ссылка}`, `{контакт}` берутся из отклика. Рядом с кнопкой «Копировать» есть выбор отклика, по умолчанию последний добавленный. Если в тексте есть переменная, которой нет в отклике (например `{имя}`), при копировании появляется маленькая форма, чтобы её заполнить. Подстановку видно в превью.
- В карточке отклика кнопка «Скопировать сопроводительное» открывает список текстовых записей; выбранная копируется с подставленными данными этого отклика.
- После копирования показывается уведомление «Скопировано».

### Чтение и запись данных

- Данных мало (сотни строк), поэтому вкладка читается целиком одним запросом и кэшируется на сервере; после записи кэш сбрасывается (`revalidateTag`).
- Обновление: найти строку по `id`, переписать её одним запросом. Удаление: удалить строку по найденному индексу (индекс берётся сразу перед удалением).
- При ошибке лимитов Google (429) запрос повторяется с паузой; после нескольких неудач пользователь видит ошибку.
- Пишет один пользователь, поэтому конфликты не решаются: последняя запись побеждает.
- Если при чтении строка не проходит проверку (нет `id`, неизвестный статус), она не роняет страницу: пропускается и записывается в лог сервера.
- Если в новой таблице нет нужных вкладок или заголовков, приложение создаёт их само при первом запуске.

### Перенос старых данных

Одноразовый скрипт переносит записи из старой таблицы в новую. **Перенос — последняя задача плана**, остальное от него не зависит.

**Как читать старые данные.** Скрипт читает старую таблицу через тот же Sheets API: пользователь даёт служебному аккаунту доступ к старому файлу «только чтение». Выгрузку через `gviz/tq?tqx=out:csv` **не использовать**: проверка показала, что она молча выбрасывает значения, если в колонке смешаны числа и текст. Например, в колонке ЗП пропали «2500(в вакансии указано 4000-6000)» и «120 000 — 200 000».

**Что в старой вкладке «отклики»** (прочитано 2026-11-23):

- 216 строк. Колонки: `дата` (везде `ДД.ММ.ГГГГ`), `компания`, `линка`, `должность`, `ЗП`, `1 собес`, `2 собес`, `3 собес`, плюс колонка I (о ней ниже).
- `линка`: 27 ячеек содержат две ссылки (например lnkd.in + linkedin.com, dou + сайт компании). В `url` идёт первая ссылка, полный текст ячейки сохраняется в `notes`. Источники по количеству: LinkedIn 52, DOU 46, Djinni 33, Ashby 20, work.ua 9, nofluffjobs 8, arbeitnow (разные домены) 12, Greenhouse 8, robota.ua 6, himalayas 4 и единичные сайты компаний. Список `source` нужно дополнить: `nofluffjobs`, `arbeitnow`, `himalayas`, `smartrecruiters`, `dover`; `lnkd.in` считать LinkedIn.
- В одной строке в колонке `компания` стоит ссылка, в двух — в колонке `должность`. Такие строки идут в отчёт для ручной проверки.
- `ЗП` заполнена в 48 строках: чаще всего просто число (2500, 3000 — доллары), есть числа в гривнах (30000, 50000, 70000) и диапазоны с текстом. Переносится в `salary_asked` как есть, текстом, без пересчёта валют.
- `1 собес` заполнена в 62 строках, `2 собес` — в 2, `3 собес` пустая. Отмечено только текстом, ячеек «только цветом» нет (подтвердил пользователь).

**Правила разбора колонок «собес»** (проверить тестами на этих реальных строках):

| Текст в ячейке | Результат |
|---|---|
| `реджект 02,09` (54 строки), `реджект 1109-изменили требования…` | `rejected` на эту дату; хвост после даты — в заметку к записи истории |
| `позиция уже закрыта 27,10`, `звкрыли вакансию 30.10`, `закрыли вакансию, дали ссылку…` | `rejected` с заметкой «вакансия закрыта» (если даты нет — дата отклика) |
| дата без слов в `1 собес` (`13.10`) | `interview`, этап 1, на эту дату |
| текст с датой в `2 собес` (`16,10 техническое`) | `interview`, этап 2, текст — в заметку |
| остальное (`09,09 написали что… дадут фидбек`, `9.11 получил письмо с анкетой…`) | `screening` на первую найденную дату, полный текст — в заметку |

- Даты пишутся как `ДД,ММ`, `ДД.ММ`, `ДДММ` или `Д.ММ`. Год берётся из даты отклика; если дата получается раньше отклика, берётся следующий год.
- Ссылки в ячейках «собес» сохраняются в `notes`.
- Итоговый статус отклика — последний по дате этап. Каждая запись получает начальную `sent` в `history` с датой отклика.
- Всё, что не подошло под правила, попадает в отчёт для ручной проверки, а не теряется.
- Скрипт можно запустить повторно: перед записью он проверяет, нет ли уже такой записи (компания + ссылка + дата).
- Старые отклики без движения после импорта честно получат пометку «нет ответа 30+ дн», и их можно массово отметить как Тишину. *(Моё решение: это отражает реальность.)*

**Колонка I — заготовки для Копилки.** В её заголовке и 7 ячейках лежат сопроводительные письма (английское и украинское) и несколько ссылок. Скрипт переносит их в Копилку: тексты — в раздел «Шаблоны», ссылки — в раздел «Ссылки», и больше их нигде не использует.

### Мелкие решения *(мои, можно поправить)*

- Часовой пояс — Киев (`Europe/Kyiv`): «сегодня» по умолчанию, `next_event_at`, расчёт «за 7 дней».
- Смена статуса по умолчанию датируется текущим моментом, но дату можно поменять (если забыл записать вовремя).
- Карточка, перенесённая на доске в «Собеседование», получает этап на 1 больше предыдущего (или 1, если раньше собеса не было); номер этапа можно поправить в карточке.

### Настройка (инструкция в README)

1. Создать Google Cloud-проект, включить Sheets API, создать служебный аккаунт и скачать JSON-ключ.
2. Создать OAuth-клиент для входа через Google, указать redirect URL от Vercel.
3. Создать пустую Google-таблицу и дать служебному аккаунту доступ на редактирование.
4. Прописать переменные окружения в Vercel: `GOOGLE_SERVICE_ACCOUNT_JSON`, `SPREADSHEET_ID`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET`, `ALLOWED_EMAIL`.
